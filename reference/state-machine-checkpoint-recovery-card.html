安全恢复速查：状态、记录与存档

对话历史让模型知道“发生过什么”；业务状态让程序确认“现在还能做什么”。两者缺一不可。

三个对象，各自回答一个问题

对象回答的问题最少应保留什么
任务状态机现在处于什么阶段，下一步允许什么？created、planning、running、waiting_tool、tool_failed、waiting_approval、completed、failed、cancelled；以及合法迁移。
步骤执行记录具体做过什么，结果和证据怎样？计划进度、工具调用 ID、输入输出、失败原因、重试、下步决策、证据与预算消耗。
Checkpoint下次如何有依据地重建任务？任务、计划、记录、证据、会话引用、工作区与代码版本/摘要、运行计数、待审批动作与决定。

恢复协议

1. 校验存档：格式、必填字段、版本、完整性/校验和
2. 核对现场：工作区、文件/代码版本、未确认的工具结果
3. 检查规则：是否终态、审批是否仍有效、预算是否尚存
4. 还原对象：计划、步骤记录、证据、计数
5. 再续跑：准备上下文后才调用 Agent Loop

关键规则：结果不明的写操作不能自动重放。Checkpoint 说“尚未写入”，但工作区可能已经变了；先输出核查信息并停止自动推进。

最容易混淆的边界

不要这样推断正确判断
会话能续接，所以任务能安全恢复。会话只恢复上下文；任务恢复还要核对真实工作区与业务记录。
工具成功，所以任务完成。工具成功只是一次动作结果；完成还需要计划步骤、验证与交付证据满足契约。
工具失败，所以任务失败。tool_failed 是一次调用的结果；任务可重试、改计划或安全停止。
暂停，所以任务已取消。任务阶段和停止原因分开记录；INTERRUPTED 的 running 任务仍可能可恢复。
收到终止请求，所以操作已停。停止请求、禁止新操作、已启动操作真实结束是三件不同的事。

审批门禁

修改源码前：保存具体动作 → waiting_approval
批准时：重新核对动作参数和关联文件内容
未变且批准：waiting_approval → running → 执行
拒绝或授权失效：不得执行该写操作

批准绑定具体动作，不因重启默认继承；补丁参数或关联文件内容变化后，旧授权无效。

恢复验收最小集

  • 异常发生在写入与下一次存档之间时，检测到差异并阻止重复写入。
  • 测试中断且无完整结果时，绝不标记验证通过。
  • 等待审批时，批准前与拒绝后均没有写入；批准仅执行对应补丁。
  • 损坏存档、缺失工作区或终态任务被明确拒绝恢复，且不启动模型或写工具。
  • 恢复后保留历史失败、轮数、重试次数与预算消耗。
