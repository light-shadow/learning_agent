最小可验证计划模板

适用于首个单进程 Coding Agent：先让规则正确、可测，再考虑持久化、并发和多 Agent。

四个对象

对象必须包含不负责什么
Plangoal、constraints、version、steps、revisionCount不直接保存模型的自然语言推理。
PlanStepobjective、dependsOn、successCriteria、status、evidenceIds不自行产生证据或绕过依赖。
EvidencestepId、toolCallId、artifactVersion、kind、payload不等于模型的总结或结论。
CompletionContract任务级必备条件与验证函数不替代每个步骤的验收条件。

Java 8 形状

enum StepStatus { PENDING, IN_PROGRESS, COMPLETED, BLOCKED, SKIPPED, FAILED }

class PlanStep {
String id; String objective; List<String> dependsOn;
List<String> successCriteria; StepStatus status; List<String> evidenceIds;
}

class Evidence {
String id; String stepId; String toolCallId; long artifactVersion;
EvidenceKind kind; Map<String, Object> payload;
}

interface CompletionContract {
CompletionResult verify(CompletionContext context);
}

不可省略的规则

  1. 只有所有依赖步骤为 COMPLETED，当前步骤才能开始。
  2. 模型只能请求完成；程序校验证据存在、归属正确、版本新鲜且符合 successCriteria 后才改变状态。
  3. 代码版本变化后，旧版本的 test / diff 证据不能证明新版本的修复完成。
  4. 步骤完成不等于任务完成；Completion Contract 还要检查全局交付条件。
