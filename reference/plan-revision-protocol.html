计划修订协议速查

修订是对路径和依赖的原子变更，不是把失败隐藏为“完成”，也不是降低验收标准。

什么时候修订？

观察到的事实正确处置是否 revise_plan
命令文件路径拼错修正参数并重跑否，局部纠错
幂等查询短暂超时在预算内受控重试否
证据推翻根因假设替换错误修复步骤，重连下游依赖是
测试环境缺少 fixture新增环境准备步骤是
用户增加“不得改公共 API”约束使冲突步骤失效，修正 diff 并重新验证是
权限被拒或预算耗尽记录 BLOCKED / 停止原因否，不能靠改计划绕过限制

RevisionRequest 最小字段

expectedVersion：基于哪个计划版本提出
reason：哪项新事实改变了前提
evidenceIds：支持该事实的真实证据
changes：replace / add / rewire 等变更

原子提交

1. 比较 expectedVersion
2. 检查 revisionCount < maxRevisions
3. 在候选副本应用 replace / add / rewire
4. 校验：ID 唯一、依赖存在、无环、约束未被降低
5. 全部通过 → version + 1，并追加 revision record
任一步失败 → 原 Plan 一个字段不变
