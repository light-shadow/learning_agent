Function Calling 与 Tool Runtime 速查卡

一句话：模型提议结构化动作，Runtime 用可信上下文决定并记录是否执行。

用户目标 → LLM 生成 Tool Call → Runtime 校验 / 授权 / 执行 / 观测
→ Tool Result（保留原 tool_call_id）→ LLM 继续决策

职责不能混淆

层负责什么绝不能负责什么
模型 / Function Calling根据可见 Schema 选择工具，产生名称、调用 ID、JSON 参数。直接执行 handler；声明自己有权限、已审批或降低风险。
Tool Runtime冻结可执行工具集，校验输入，读取身份与审批，执行门禁、超时/重试策略、审计和结果关联。相信模型参数就是可信身份；把非幂等写操作超时后一律重试。
Handler在门禁通过后执行确定的业务操作并返回业务事实。承担模型协议、模型选择或绕过 Runtime 的权限检查。
Agent Loop把 Tool Result 写回同一轮上下文，决定继续调用、追问或结束。用模型的 Final 文本伪造工具执行成功。

一份完整 Tool Definition

字段用途示例
name / description让模型正确选择，明确能做与不能做的事。search_orders：只读订单，不能取消或退款。
Input Schema阻止错误参数进入 handler。状态枚举、日期范围、数量上限。
Output Schema把成功事实固定为 Loop 能消费的稳定结构。订单 ID、状态、金额、创建时间。
Error Schema让恢复策略依据错误类别，而非猜自然语言。INVALID_ARGUMENT、TIMEOUT、APPROVAL_REQUIRED。
permission / risk声明治理要求，供 Runtime 执行。order:read、high。

可信边界

来源例子处理方式
不可信：Tool Call订单号、筛选条件、任何 JSON 字段。Input Schema + 业务规则校验；不合格时 handler 调用次数必须为 0。
可信：Execution ContextuserId、租户、角色、审批凭据、Trace ID。由登录态或服务身份注入，不出现在模型可填写的 Input Schema。
受检：Handler 输出数据库或上游 API 返回对象。通过 Output Schema；不合格转为 INVALID_OUTPUT。

关联与重试

tool_call_id 是候选调用、执行记录、Tool Result 与 Trace 的关联键。并行的同名调用可以乱序完成；结果必须按原 ID 回写，绝不能按返回顺序猜配对。

只读查询发生短暂超时，可在有限预算内重试。取消订单、扣款等非幂等写操作超时，只说明调用方未知结果；先查询或走幂等键/状态确认，不能盲目再执行。
