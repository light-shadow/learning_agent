Planning 验收测试矩阵

规则正确、接线正确、真实运行正确，是三种不同的结论，缺一不可。

层级必须证明代表性观察
PlanStore 确定性测试状态机、证据、依赖和修订规则正确。未就绪 start 被拒；旧版本证据被拒；有环修订后快照完全不变。
Loop 集成测试门禁真的位于 Runtime 之前，证据与停止契约真的接线。缺 planStepId / 未就绪时 handler 调用次数为 0；Final 不足时 Follow-up 继续。
真实运行真实模型、真实工具、真实代码与实际环境能形成闭环。源码真的改动；测试真的运行；计划与证据摘要、交付文档真实存在。

报告格式：不要把“做了”写成“验证了”

已实现：哪些类型、Handler、Hook、测试被加入
已验证：运行了什么命令，exit code 是什么，观察到什么行为
未验证：环境限制、预算限制、未覆盖的真实路径及其原因

高价值反例

  1. 缺证据申请完成 → PLAN_COMPLETION_REQUIRES_EVIDENCE。
  2. 证据归属其他步骤 → PLAN_EVIDENCE_STEP_MISMATCH。
  3. 旧版本通过结果 → PLAN_EVIDENCE_STALE。
  4. 修订形成依赖环 → PLAN_DEPENDENCY_CYCLE，整个计划不变。
  5. 工具门禁拒绝 → Runtime handler 调用次数为 0。
