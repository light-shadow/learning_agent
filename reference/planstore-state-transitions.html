PlanStore 状态转换速查

PlanStore 是计划状态的唯一写入者。模型提交意图，PlanStore 校验后才提交状态变化。

操作允许条件拒绝示例
start(step)步骤为 PENDING，且所有 dependsOn 均为 COMPLETED。PLAN_STEP_NOT_READY
complete(step, evidenceIds)步骤进行中；证据存在、归属正确、版本新鲜，并满足 successCriteria。PLAN_EVIDENCE_STEP_MISMATCH、PLAN_EVIDENCE_STALE
block / fail(step)记录实际阻塞或失败原因，停止伪造进展。不能把预算或权限问题改写成 completed。
skip(step)没有下游依赖；否则先通过 revise 原子改接依赖。PLAN_SKIP_REQUIRES_REWIRE
revise(plan)版本一致、有理由和证据；候选计划无环、依赖存在、未超修订预算。PLAN_VERSION_CONFLICT、PLAN_DEPENDENCY_CYCLE

最小门禁伪代码

beforeToolCall(call) {
if (!requiresPlanStep(call.name)) return;
String stepId = require(call.arguments, "planStepId");
planStore.assertExecutable(stepId);
call.arguments.remove("planStepId");
}

afterToolCall(call, result) {
evidenceStore.append(fromRuntimeResult(call, result, currentCodeVersion));
}

planStepId 是编排字段，绝不能作为业务参数传给 Runtime。被拒绝时，Runtime handler 的调用次数必须为 0。
