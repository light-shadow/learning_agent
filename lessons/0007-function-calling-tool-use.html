本讲全部核心

协议部件保护的边界
name + description + Input Schema模型选择什么、能填写什么；工具描述还要说明“不会做什么”。
Output Schema把 handler 成功事实固定成 Loop 可消费的结构，不能直接返回随意字典。
Error Schema区分参数错、权限拒绝、需审批、超时、上游失败、无效输出，驱动恢复而不是猜测。
tool_call_id绑定候选调用、异步执行、结果和 Trace；同名调用乱序完成时绝不按顺序猜配对。
Execution Context从登录态注入 user、tenant、权限、审批与 trace；绝不能由模型填写。

两种“再试一次”

Runtime 重试只针对同一只读/幂等调用的短暂故障，次数受预算控制。Loop 修正是模型读到 Tool Result 后更换参数、工具或追问。取消订单超时可能已成功，应查状态或用幂等键，不能直接再取消。

最强验收不是“返回了一段拒绝文案”，而是构造越权、额外字段或缺审批的 Tool Call，断言结构化错误且 handler 调用次数为 0。
