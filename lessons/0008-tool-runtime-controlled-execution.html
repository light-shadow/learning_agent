Tool Runtime：让候选动作进入受控执行

Runtime 是所有入口共享的控制平面；CLI、模型和 MCP 都只能走 invoke()，不能直接调用 handler。

Registry → Discovery → 本轮 Snapshot → prepare → execute → finalize → Tool Result

为什么要冻结 Snapshot

Registry 说明平台有哪些工具；Discovery 按任务、策略和运行模式选择本轮开放集合；Snapshot 冻结名称与版本。模型看到的 Schema 与 Runtime 实际执行必须来自同一份 Snapshot。新版本灰度、启停和目录刷新应在下一 Run 生效，而非当前 Run 悄悄换实现。

ToolDefinition 的两面

模型可见运行侧私有
名称、描述、参数 Schema。版本、输出/错误 Schema、权限、风险、超时、重试、审计、依赖、handler。

三阶段不可颠倒

  1. prepare：从 Snapshot 找工具，校验参数，从可信 Context 读身份，检查权限、批准、当前启停和依赖。
  2. execute：只接收已验证参数；按副作用、幂等性和预算执行超时/重试。
  3. finalize：校验输出或归一化错误，脱敏、补审计、保留原 tool_call_id。

before Hook 适合执行前的权限、风险、批准、依赖检查；after Hook 适合已验证结果后的审计与脱敏，不能假装撤销已发生写入。
