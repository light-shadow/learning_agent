Structured Output：让模型决策可校验、可恢复、可执行

Prompt 规定模型应怎样决策；Structured Output 判断系统实际收到了什么决策。

从字符串到可执行协议

关键词解析脆弱、不可扩展，也不能表达字段类型、必填条件、枚举和跨字段关系。JSON Schema 描述公开协议；Pydantic 以同一模型定义类型、生成 Schema、校验 JSON、得到程序对象。工程师决定谁消费输出、输出决定什么、允许哪些动作、何时缺字段不能执行、错误如何恢复。

三层校验与全有或全无

原生 Structured Output / JSON 语法 → Schema / Pydantic → 业务规则 → 合法对象或稳定错误

JSON mode 只保证形状可能像 JSON；原生约束强化字段结构；本地 Schema 与业务防线仍不可省。一次校验失败就不让部分对象进入 Loop，避免“有些字段合法所以先执行”。

纠错、降级与停止

将字段级、可操作的校验原因回传模型修正，并限制次数。多次失败应降级、请求用户澄清或明确停止；不能无限反问模型，也不能放宽 Schema。协议版本、错误码和验收样例都要随服务演进。

2. Schema 缺少 edit 所需路径，程序应？
