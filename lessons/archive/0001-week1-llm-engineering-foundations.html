从模型 API 到可治理的 LLM Gateway

第一周不是学“怎么发一个请求”，而是建立 Agent 的模型调用底座：可替换、可校验、可观测、可恢复。

本课胜利条件：你能用一张图说明模型调用、流式事件、提示词契约、结构化输出和 Gateway 分别在哪里收口，并知道每类失败应由谁处理。

六份讲义，收成一条主链

受控输入 → Prompt 契约 → Provider Adapter → 普通/流式响应 → Schema 校验 → Trace、预算与恢复策略
讲义必须带走的工程判断
模型 API 与 Harnessmessages 是可裁剪、可审计的运行时上下文；temperature 控制随机性，不控制正确性；max_tokens 是输出预算和截断边界。
Streaming流式不让模型更快，只改善首字节体验和过程可见性。把供应商 chunk 归一为版本化 Harness Event；断线重放事件，不拼接模型 token。
Prompt EngineeringSystem Prompt 是可版本化行为契约：角色、目标、边界、格式、few-shot 和不可信数据必须分层；注入防御从“指令与数据分离”开始。
Structured OutputPrompt 要求 JSON 不等于协议正确。依次做原生约束/JSON 解析、Schema 校验、业务规则；失败只带字段级反馈且有限重试。
LLM GatewayGateway 不是透明代理：它拥有内部请求/结果模型、Provider Adapter、模板版本、能力路由、重试、流式和 Trace。
阶段一服务外部 OpenAI-compatible API 在 API 层终止；内部按能力、优先级、成本和健康度路由，保留拒绝原因、用量、成本、延迟与关联 ID。

三条不可交换的边界

上下文

足够且必要

为输出预留 token；不能把全量日志塞进上下文挤掉任务目标。角色、来源与顺序不可压成一大段字符串。

流式

事实与传输分离

Loop 生产 run.started、tool.completed 等事实事件；SSE/CLI/Web 只消费和渲染。取消必须传播到后台 Run 和工具。

失败

先分类再处理

认证/Schema 错误不重试；网络、429、5xx 才能有限退避；首个流式内容发出后不能透明 fallback；截断的 JSON 不可勉强解析。

供应商

Adapter 隔离

SDK 对象不离开 Provider。Loop 依赖能力接口，Gateway 负责模型别名、密钥、路由、重试和观测。

最小验收清单

  1. 未知模型、缺模板变量、Schema 不合格会返回稳定错误，而不是 500 或“看起来像 JSON”的文本。
  2. TTFT 从首个非空文本 delta 计算；事件有 run_id、递增 seq 和终态。
  3. 同一请求只有一个明确的重试所有者；Trace 记录 prompt/version、实际模型、token、cost、latency 与路由决策。
  4. Agent Loop 不保存供应商密钥，也不直接实现 Provider 重试。
