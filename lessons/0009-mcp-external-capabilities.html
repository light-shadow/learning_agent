MCP：标准化接入，不替代治理

MCP 解决外部能力如何发布、发现与调用；它不替你决定权限、风险、审批、审计或 Agent 下一步。

MCP Server 发布 → Host 的 MCP Client 发现/转换 → Tool Runtime 校验/执行 → Loop 回灌结果

先辨清四个角色与三类原语

对象职责与边界
Host / Client / ServerHost 持有 Agent 会话与编排；Client 是 Host 到一个 Server 的协议连接；Server 暴露能力，但不天然可信。
Tool带参数执行查询或动作；进入 Host 的 Runtime 后才可真正执行。
ResourceURI 标识的只读上下文，不能伪装为写操作。
Prompt预定义交互模板；不等于 Host 的安全/业务策略。

接入的关键约束

  1. 一个 Run 缓存并冻结工具目录；模型侧工具用 server_id.tool_name 限定名，防止多 Server 同名覆盖，也让审计能定位来源。
  2. stdio 的信任边界包括可执行文件、参数、工作目录与环境变量；不能让模型控制启动命令或无筛选转发密钥。
  3. 适配器将 Server 结果限制大小、归一化为本地 Output/Error 协议，再由同一 Runtime 返回 Tool Result；错误事实交给 Loop 决策恢复。
  4. 测试要证明成功、参数拒绝、Server Tool Error、网络失败和可能重复副作用的恢复路径，而不只看最终文本。
