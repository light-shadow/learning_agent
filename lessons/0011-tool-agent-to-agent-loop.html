从一次调用，到可停止的 Agent Loop

复杂 Coding Agent 不是“多调用几次工具”，而是在观察世界后持续决策、行动、验证，直到完成契约通过或真实停止。

Think / Decide → Tool Call → Runtime → Tool Result / Evidence → 下一轮；LoopGuard 决定还能否继续

什么时候需要自主 Loop

目标清晰、环境可访问、动作可验证时，Loop 能处理搜索、阅读、写产物与验证等未知路径。简单确定性流程用 Workflow；跨模块修复需要显式 Planning；Loop 是执行发动机，Plan 是全局导航，不能互相替代。

运行中的四层责任

层职责
Tool Runtime单次动作是否允许、如何执行、怎样包装结果。
Agent Loop把 Tool Result 按 ID 写回模型上下文，决定下一轮或文本结束。
LoopGuard最大轮数、重复动作、取消、预算和不可继续的 Provider 结果。
Completion Contract证明业务完成，而不是把模型的 Final 或无 Tool Call 当作完成。

最小 Coding Agent 与验收

将“分析登录逻辑并写 Markdown”拆为 list/search/read/write 四种 Runtime 工具。动作指纹是工具名加规范化参数；同一动作第三次应在 handler 前拒绝。每轮只处理一个可验证事项；工具结果、真实错误、完成缺项都进入下一轮 Context。

  1. 脚本化响应测试：Tool Result 回写、提前 Final 被拒绝、第三次重复动作 handler 仅两次、最大轮数、取消传播。
  2. 真实集成：Gateway/模型能走完搜索→阅读调用链→写产物→验证；不能用“最终文档存在”代替这些边界测试。
  3. 恢复不是重新发送 Prompt：写入、Git、外部调用可能已发生，状态与现场核对交给后续 Checkpoint。
