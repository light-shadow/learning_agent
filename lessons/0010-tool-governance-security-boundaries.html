工具治理：让不该执行的动作止于副作用之前

治理不追求“所有调用成功”，而是让应该执行的动作可证，让越权、篡改与不安全重试在 handler 前停止。

四个控制阶段

阶段必须落实的规则
分级与权限按读/写、副作用与风险定义 RBAC/ABAC、资源归属和审批；批准绑定 user、tenant、tool、规范化参数与有效期。
调用期安全Schema 之后还要业务预检：状态、额度、资源归属。只读/幂等故障可有限重试；结果不明的写操作先查状态。
编排与队列仅独立、无资源冲突的调用并发；把完成顺序与消息关联分开，结果仍按 tool_call_id 回写。
审计与观测用 trace_id、tool_call_id 与业务 ID 串决策和执行；模型消费脱敏最小视图，诊断通道保存受保护细节。

硬约束与验收

唯一入口 invoke()；prepare = 查找 → Pydantic 校验 → 权限三态；DENY/CONFIRM 立即返回结构化结果且 handler=0

错误码应让 Loop 知道下一步：INVALID_ARGUMENT 可修参数，SHOP_NOT_FOUND 应追问，PERMISSION_DENIED 不可重试，APPROVAL_REQUIRED 进入人工流程。测试必须断言副作用计数：越过白名单、伪造身份、修改审批绑定参数、写操作超时，各自不能产生未经授权的第二次执行。
