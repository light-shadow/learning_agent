Working Memory：维护当前任务的可核对状态

聊天历史记录发生过什么；工作记忆直接回答当前任务已经做成什么、还缺什么、下一步可做什么。

当前任务记录的最小模型

goal + constraints + risks + completedSteps + facts + unresolved + scratchpad + currentArtifactVersion

例如修复 `SessionService` 的边界条件时，记录目标、不得修改测试的约束、已读取文件与失败测试、尚未应用补丁和未重新验证等事实。风险要写明可能影响、依据、下一步核查；未确认风险标为待确认。

事实、提议、原文各自保存

对象能写什么必须带什么
原始 Tool Result完整执行输出tool_call_id、执行记录
工作记忆事实当前判断所需摘要source、executionId、artifactVersion、原文 reference
Scratchpad拟议路径、观察、下一步关联证据；明确“尚未验证”

“把 `<=` 改为 `<`”是提议，不是补丁已写入；只有 Runtime 回执才能把进度更新为真实完成。

保存不等于每轮全量发送

工作记忆要持久保存，防止进程退出后丢失；装配器再按本轮目标、证据有效性和 Token 预算选择其中相关部分进入模型输入。它也不同于 Agent State：后者还保存消息、模型、工具快照与运行标记。

恢复时先核对现场

工作记忆告诉系统上次记录到哪里，却不能证明文件、分支或外部系统没有变化。恢复时，先核对当前版本与未决动作，再依据真实结果更新事实；不能将过期测试结果继续当作当前证据。
