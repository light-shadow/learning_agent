Sandbox：让 Agent 的真实影响有边界

能力越完整，越要限制文件、进程、网络与资源。Sandbox 不是提示词，而是覆盖实际执行入口的技术控制。

两种课堂路径

方案本质与验收重点
pi-sandbox为本地 pi 的读写、shell、网络、浏览器进程与授权提示配置边界；手工 ! 命令也必须经过沙箱。验证允许在 artifacts 写/读，越界路径和未授权访问被拒绝。
OpenSandbox + Docker宿主 Python 驱动容器；验证创建、执行、取回结果和回收，证明宿主标记文件未出现在容器。演示执行隔离不自动代表已限制外网。

真实项目的最小规格

  1. 按风险选择隔离强度；明确允许读什么、只允许写哪里、哪些命令/域名可用、资源与超时上限。
  2. 先让文件工具、Shell 和子进程全部进入受控入口；路径检查覆盖 ..、绝对路径与符号链接。
  3. 从只读项目、受控产物写入、固定测试小步验收；网络和浏览器进程默认关闭，授权超时保持拒绝。
  4. Sandbox 提供影响范围，Runtime/Governance 仍负责权限、审批、审计、取消和完成证据。

1. 工具参数包含 artifacts/../../secret.txt，沙箱应？

2. 验收 Sandbox 是否有效，优先检查规则是否覆盖真实？
