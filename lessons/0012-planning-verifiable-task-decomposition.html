Planning：把复杂任务拆成可验收的子目标

计划不是让模型“多想一步”，而是持久化当前路径假设、依赖、证据与完成条件，并能拒绝不合法推进。

先选对执行结构

任务特征适合结构
固定、步骤和分支已知Workflow。
下一步依赖观察，但子目标少Agent Loop / ReAct。
跨模块、持续追踪依赖、证据和交付条件显式 Plan + Loop。

Planning 管“先完成什么、还缺什么、何时换路径”；Runtime 管单次许可；Loop 管结果回写；Verifier/Completion Contract 管是否真的交付。

一份可执行计划

每个步骤写完成后新增的事实、dependsOn、成功标准与可接受证据，而不是“分析、修改、测试”三句口号。Evidence 由 Runtime 写入，绑定 stepId、toolCallId、种类与 artifactVersion；当前代码变了，旧通过测试仍真实却不能为新版本背书。

ready = pending 且所有 dependsOn = completed；complete 需要归属正确、版本新鲜、数量足够且覆盖 success criteria 的证据

局部纠错与计划修订

参数拼错、可重试查询超时通常局部纠错；根因、目标、模块结构或约束被证据推翻才修订。修订带 expectedVersion、原因、证据和替换内容，先在候选副本中校验重复 ID、缺失依赖与环，再原子提交。模型可改路径，不能降低验收标准。

接回既有 Loop

Hook新增行为
prepareNextTurn注入计划版本、就绪步骤与证据摘要，保留原 Tool Result。
beforeToolCall检查受约束调用的 planStepId 和步骤就绪；拒绝时 handler=0。
