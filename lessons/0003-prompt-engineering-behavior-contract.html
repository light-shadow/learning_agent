Prompt Engineering：把提示词做成行为契约

模型可以帮你写 Prompt 草案，但角色、边界、数据来源、版本和验收属于工程责任。

一份工程化 Prompt 的组成

部分要回答的问题
System Prompt长期角色、目标、稳定规则、优先级和禁止边界；“资深专家、认真分析”不是可测约束。
任务与风格按消费场景规定格式：CLI 要短且状态明确，代码审查要风险、位置与建议。
Few-shot给典型正确输入/输出和边界反例，校准“合格结果长什么样”。
任务拆解分析→执行→检查，让中间结果可检验；不是让模型一次完成所有事情。
模板名称、版本、变量 Schema、长度/内容边界、示例与回归样例，使一次性字符串成为可发布组件。

注入与版本

稳定指令放 System Prompt；外部网页、文件、用户内容是数据而非指令，明确分隔、限制能做什么、按来源处理。Prompt 注入不能靠“请忽略恶意内容”解决。版本号记录语义变化，Trace 标出实际模板/版本；每次变更绑定最小回归集，才知道线上行为为何变化。
