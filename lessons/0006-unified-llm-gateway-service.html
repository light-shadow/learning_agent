阶段一：把 Gateway 做成可部署服务

从单文件语义验证，演进到 OpenAI-compatible、配置化、可路由、可观测的模型调用服务。

外部兼容，内部自治

OpenAI-compatible API 只停在 API Layer；Gateway 内部有自己的请求、结果、错误与事件模型。上游 Agent 声明逻辑模型与能力需求，Router 决定实际 Provider/模型；这样供应商、地址、密钥与版本变化不会泄漏入业务 Agent。

完整的运行链

组件职责
API / 鉴权限流兼容 Chat/Responses 的外部 Schema，身份、租户、配额和输入边界。
Capability Registry / Router按 streaming、structured output、tool calling 等能力、优先级、成本与健康度选路由；记录候选拒绝原因。
Prompt Bundle系统模板、变量 Schema、few-shot、版本与 hash，是可发布单元而非字符串仓库。
Executor统一普通响应、流式事件和结构化输出；流式首内容后不可透明 fallback，终态只能有一个。
Trace / Usage关联 trace_id、run_id、step_id、call_id，记录逻辑模型、实际模型、Prompt、token、cost、latency、错误与路由。

弹性与测试

认证和本地校验错误不重试；预算/变量问题先修正请求；可恢复上游故障才有限重试与 fallback，且顺序可配置。通过 MockTransport 做 Adapter 合约测试，通过 Router 测试验证能力匹配、优先级、fallback 与拒绝原因；再做流式、结构化、限流与端到端集成验收。Loop 只依赖 Gateway 模型端口，工具、循环和状态不下沉到 Gateway。
